# Oracle PL/SQL Book Management System

This is a library lending and inventory project, kept separate from the Flask online bookstore in the parent folder. It targets Oracle 12c+ (including 23ai) and uses identity columns, constraints, and the `BOOK_MANAGEMENT_PKG` PL/SQL package. IDs are generated by Oracle identity columns; no hand-maintained sequences or stock triggers are needed. The package never commits: your session controls transaction boundaries. `ISSUE_BOOK` uses a savepoint so a failed issue attempt cannot leave its stock decrement behind.

## Architecture

`AUTHORS`, `CATEGORIES`, and `PUBLISHERS` each have a one-to-many relationship with `BOOKS`. `MEMBERS` and `BOOKS` each have a one-to-many relationship with `BOOK_ISSUES`; issues are retained after return. Foreign keys intentionally block deleting referenced people/catalog rows or books with history. Members with history are retained. `available_stock` is the count currently available to lend; issue/return procedures change it exactly once.

## 1. Check Oracle on Windows and identify the connection

Use Windows Services (`services.msc`) to check that the Oracle database service is Running. Common service labels include `OracleService<SID>`; names vary by installation. In Command Prompt, `where lsnrctl` checks whether the listener utility is on PATH. Run `lsnrctl status` to see the listener endpoint and services it advertises. The listener port is shown as `HOST=... PORT=...` (often 1521, but use what your output says). The database service name is shown in the listener's Services Summary.

If you can access the database host, connect with an authorized admin account in SQL Developer and run:

```sql
SELECT name, open_mode FROM v$database;
SELECT name, pdb FROM v$services ORDER BY name;
```

These dynamic performance views may require DBA privileges. Alternatively run `lsnrctl status` locally or ask the database administrator for the PDB service. Do not guess `FREEPDB1`, `ORCL`, `XEPDB1`, or any other service. For a multitenant database, create the app user in the intended open PDB, not in the root container. If SQL Developer cannot connect, verify host reachability, listener status/port, exact service name, user/password, and PDB state. `ORA-12514` usually means the listener does not know the requested service; `ORA-12541` means no listener is reachable at that host/port; `ORA-01017` means credentials are invalid.

In SQL Developer, click **New Connection** and enter a connection name (for example `BOOK_APP`), username, password, hostname, listener port, and the exact **Service name** obtained above. Choose **Basic**, select **Service name**, click **Test**, then **Connect** after the test reports success. Use a separate authorized administrative connection for user creation, then reconnect with BOOK_APP.

## 2. Create the application schema

Open `01_create_user.sql` using the administrative connection in the target PDB. Replace the example password and verify the intended tablespace/quota first. Run with **F5 (Run Script)**. The script requests only session, table, procedure, and trigger creation privileges. If your organization provisions users centrally, have the DBA create the same schema/grants instead. Now make a `BOOK_APP` SQL Developer connection and run all remaining scripts using it.

## 3. Install objects (in order)

In the BOOK_APP connection, open and run each file below with **F5**. SQL*Plus `/` terminators and `SET SERVEROUTPUT` require Run Script; F5 also shows DBMS Output. Add the DBMS Output panel from **View → DBMS Output**, click its green plus, and select BOOK_APP.

1. `02_create_tables.sql` — tables, identity primary keys, integrity constraints, and indexes.
2. `03_create_package_spec.sql` — public procedures/functions.
3. `04_create_package_body.sql` — complete implementations.
4. `05_sample_data.sql` — rerunnable sample catalog, five authors/categories/members, three publishers, ten books. It inserts missing rows by unique natural keys and commits.
5. `06_test_crud.sql` — temporary author/category/publisher/member/book create, read, search, update, delete smoke test.
6. `07_test_issue_return.sql` — verifies issue stock decrement and return restoration, then rolls the test transaction back.
7. `08_report_queries.sql` — report queries; run all with F5 or individual statements with Ctrl+Enter.
8. `09_verify_database.sql` — object, error, and record-count checks.

For a package compile error, inspect the Script Output and query `USER_ERRORS`. Fix the first reported line in the package body and rerun spec/body. Successful package objects should have `STATUS='VALID'`; `USER_ERRORS` should return no rows for the package.

## 4. Call examples and transaction handling

Use **F5** for anonymous PL/SQL blocks. Example:

```sql
SET SERVEROUTPUT ON
DECLARE v_id NUMBER; v_msg VARCHAR2(4000);
BEGIN
  book_management_pkg.add_member('Demo Member','demo.member@example.test','555-0100',v_id,v_msg);
  DBMS_OUTPUT.PUT_LINE(v_msg||' ID='||v_id);
  COMMIT;
END;
/
```

`LIST_BOOKS`, `SEARCH_BOOKS`, and `GET_BOOK_BY_ID` return `SYS_REFCURSOR`. To view results, use SQL Developer's **Run PL/SQL** dialog (right-click procedure → Run) and bind the OUT cursor, or fetch it from a PL/SQL block. Typical OUT-cursor fetch shape:

```sql
DECLARE c SYS_REFCURSOR; id NUMBER; title VARCHAR2(250); author VARCHAR2(150);
BEGIN
  book_management_pkg.search_books('Orwell',c);
  LOOP FETCH c INTO id,title,author; EXIT WHEN c%NOTFOUND;
    DBMS_OUTPUT.PUT_LINE(id||' | '||title||' | '||author);
  END LOOP; CLOSE c;
END;
/
```

The example fetch list must match the cursor's selected columns; `SEARCH_BOOKS` returns eight columns. For reliable inspection, direct report SELECTs in `08_report_queries.sql` are easiest. Commit successful work explicitly with `COMMIT;`; use `ROLLBACK;` to discard the current transaction. Do not put a commit after every package call when composing a larger transaction. The seed script commits its own sample rows. The issue/return test rolls back its changes.

## CRUD/testing notes

`06_test_crud.sql` covers create/read/search/update/delete through the package for each catalog entity and member, then removes only the temporary records. For a book with history, `DELETE_BOOK` reports a clear error and the foreign key preserves history. The package prevents deleting authors, categories, publishers, or members with dependent rows. For individual retrieval use `GET_BOOK_BY_ID`; for full/search lists use `LIST_BOOKS` / `SEARCH_BOOKS`.

For explicit rejection cases, use the package calls documented at the bottom of `06_test_crud.sql` in separate blocks and catch exceptions with `WHEN OTHERS THEN DBMS_OUTPUT.PUT_LINE(SQLERRM); ROLLBACK;`. Then query the related table to verify it was unchanged. `07_test_issue_return.sql` covers successful lending and return plus exact stock restoration. To test insufficient stock, use a disposable zero-stock book and a valid member; expect `ORA-20016` then rollback. Calling `RETURN_BOOK` again for that issue expects `ORA-20018`.

Common Oracle errors: `ORA-00001` unique key violation (duplicate ISBN/email/category; use a unique value); `ORA-02291` missing parent foreign key (create/choose valid author/category/publisher/member); `ORA-02292` child rows prevent parent deletion (archive/retain parent or remove only permitted children); `ORA-01400` null in required field (supply it); `ORA-01403` no data found (package maps expected missing records to application errors); `ORA-12899` value too long (shorten input to declared column length). The package translates common business errors into `ORA-200xx` messages and re-raises unexpected errors.

## Final checks

Run `09_verify_database.sql`. It lists `USER_TABLES`, `USER_CONSTRAINTS` (via the query shown below), `USER_OBJECTS`, `USER_ERRORS`, and seeded row counts. Expected tables are AUTHORS, CATEGORIES, PUBLISHERS, BOOKS, MEMBERS, BOOK_ISSUES; package spec/body should be VALID and USER_ERRORS empty. Oracle identity metadata is reflected in `USER_TAB_IDENTITY_COLS`; this project does not create standalone sequences.

```sql
SELECT table_name,column_name,generation_type FROM user_tab_identity_cols ORDER BY table_name;
SELECT constraint_name,table_name,constraint_type,status FROM user_constraints ORDER BY table_name;
SELECT book_management_pkg.get_total_books FROM dual;
SELECT book_management_pkg.get_inventory_value FROM dual;
SELECT book_management_pkg.get_overdue_book_count FROM dual;
```

The committed sample dataset has at least 5 authors, 5 categories, 3 publishers, 10 books, and 5 members. Run the report SQL to demonstrate full inventory, low stock, author/category filtering, active/returned/overdue issues, and issue counts per member.
